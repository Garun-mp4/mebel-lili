# Документы и запуск сбора заявок в РФ

Состояние на 04.10.2026: документы подготовлены как **проекты**, реквизиты неизвестны. Плейсхолдеры разрешены пользователем. Пользователь выбрал российский хостинг для сайта и приёма заявок; Telegram — только дополнительное уведомление без полей клиента. Фактический хостинг, договор с провайдером и организационные меры пока не настроены. Соответствие всей деятельности компании закону этим изменением не подтверждается.

## Что размещено

- `/privacy.html` — единая политика конфиденциальности и обработки персональных данных: оператор, цели, категории субъектов, состав данных, основания, операции, получатели, сроки, права, безопасность и место базы.
- `/consent.html` — отдельное согласие только на ответ по заявке. Не включает рекламу, распространение или отправку полей в Telegram.
- `/cookies.html` — информация о cookies и технических данных. В приложении нет cookies, аналитики, рекламных пикселей, localStorage или sessionStorage. Баннер с формальным «принимаю всё» не добавлен. Инфраструктуру следует проверить перед запуском.
- Все три формы имеют отдельный обязательный чекбокс, снятый по умолчанию, и ссылки на согласие и политику. Ссылки есть также в подвале. Согласие проверяется и на сервере, включая актуальную версию. С плейсхолдерами браузер не отправляет поля вообще; после утверждения документов сначала проверяет готовность обработчика запросом GET без полей. При выключенном JavaScript отправка отключена.

## Реквизиты и утверждение

Единственный источник реквизитов — `legal/operator.mjs`. Замените все значения в квадратных скобках: юридический оператор, ИНН, ОГРН/ОГРНИП (или «не применяется»), почтовый адрес, рабочий email для обращений, HTTPS-домен, российский провайдер и адрес ЦОД. Адрес мастерской из архива не подставлен вместо юридического адреса без подтверждения.

Уточните у оператора фактические цели, состав сотрудников/обработчиков, инфраструктурные журналы и их сроки; при необходимости дополните `src/legal-documents.mjs`. После изменения согласия увеличьте `consentVersion` в `legal/operator.mjs` и обновите дату документов. Согласуйте документы с оператором и установите `approved: true` только после заполнения и проверки. Выполните `npm run build`: он обновит HTML-документы в `public` и сборку в `dist`. `npm run dev` и `npm run build:vite` также обновляют документы. Генерируемые HTML вручную не редактировать.

## Российский сервер

Разместите **весь сайт, Node.js-обработчик, постоянный каталог заявок, ключ и резервные копии в РФ**. Требуется Node.js 22 и постоянный диск; эфемерные файловые системы функций не подходят. Российскую географию нужно подтвердить договором/сведениями провайдера, а не только переменной окружения. При использовании Docker монтируйте отдельный постоянный том вне `/app`, доступный пользователю `node` (UID 1000); контейнер работает без root. Нельзя хранить данные в Git, `public`, `dist` или внутри каталога приложения.

1. Установите приложение, выполните `npm run build`.
2. Создайте приватный каталог, например `/var/lib/mebel-lili/leads`, с правами 700 для пользователя сервиса. На Windows настройте NTFS ACL: Node не обеспечивает эквивалент POSIX-прав автоматически.
3. Скопируйте `.env.example` в `.env.local` вне публичного доступа; на Linux установите права 600. Сгенерируйте 32 случайных байта для `LEADS_ENCRYPTION_KEY` (64 hex-символа). Не помещайте ключ в репозиторий, браузер, публичные логи или рядом с резервной копией данных. Сохраните отдельную защищённую копию ключа в РФ: без него заявки не прочитать. Перед сменой ключа обработайте/удалите старые записи; автоматической миграции ключа нет.
4. Укажите `LEADS_DATA_DIR` абсолютным путём к приватному каталогу и `LEADS_RU_HOSTING_CONFIRMED=true` после фактической проверки инфраструктуры. Без полного оператора, ключа, каталога и этого подтверждения `/api/leads` отвечает 503 до разбора тела заявки. При `VERCEL` сбор заблокирован независимо от остальных настроек. Наличие токена Telegram само по себе не включает формы.
5. Запустите `node --env-file=.env.local server.mjs` как постоянный сервис с автозапуском. По умолчанию порт 4173. Обеспечьте HTTPS через российский reverse proxy и ограничьте прямой доступ к Node-порту. Публичный HTTPS-домен в `operator.site` используется для проверки Origin за TLS-прокси.
6. При одном доверенном прокси можно установить `TRUST_PROXY=true`, только если прокси **заменяет** `X-Forwarded-For` реальным IP и Node-порт недоступен извне. Иначе оставьте false: лимит применяется к IP сетевого соединения. Дополните защиту лимитом на прокси; встроенный лимит — 5 принятых запросов в минуту на IP в одном экземпляре.
7. Настройте мониторинг доступности, места на диске и ежедневный независимый запуск `node --env-file=.env.local scripts/leads-admin.mjs purge`. Работающий сервер также удаляет просроченные записи при старте, каждый час и при записи/чтении. После истечения срока чтение записи запрещено; фоновая физическая очистка файла выполняется при ближайшем запуске очистки. При остановке сервера внешний планировщик должен продолжать очистку.
8. Внешние журналы/прокси не должны записывать тела запросов, телефоны или комментарии. Определите необходимый срок технических журналов и отразите его в политике. Согласуйте с провайдером поручение обработки и порядок инцидентов, удаления и резервного копирования. Копии заявок также подлежат ограничению срока и удалению.

## Получение и удаление заявок

После успешной записи в зашифрованный файл сервер отвечает 200 с номером заявки. В записи находятся поля, серверное время, срок, отметка о согласии, версия, полный текст согласия и SHA-256. Имя и телефон не входят в имя файла. Каталог не обслуживается HTTP-сервером. AES-256-GCM защищает конфиденциальность и целостность; это не заменяет организационные меры и оценку требований к системе.

Доступ — через авторизованный SSH-сеанс на российском сервере. Публичной панели или API чтения нет:

```bash
node --env-file=.env.local scripts/leads-admin.mjs list
node --env-file=.env.local scripts/leads-admin.mjs read НОМЕР-ЗАЯВКИ
node --env-file=.env.local scripts/leads-admin.mjs delete НОМЕР-ЗАЯВКИ
node --env-file=.env.local scripts/leads-admin.mjs purge
```

`list` показывает только номера и срок; `read` выводит данные в терминал уполномоченного лица. Не перенаправляйте этот вывод в общие логи или иностранные сервисы. Проверяйте очередь регулярно, даже если уведомлений нет. По завершении цели или обоснованному отзыву удалите заявку раньше автоматического срока, обработайте копии и оформите подтверждение уничтожения по применимым требованиям. Максимальный срок заявки и её подтверждения согласия в приложении — 30 дней, без автоматического бессрочного архива. Договорные/бухгалтерские данные, если возникнут, требуют отдельного процесса и сроков.

## Telegram

Необязательные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` хранятся только на сервере. Сообщение содержит фиксированный текст и случайный номер заявки; имя, телефон, вид мебели, комментарий и текст согласия не передаются. Ошибка бота не отменяет уже сохранённую заявку и не вызывает повторную отправку клиентом. Ретрай уведомлений не реализован; основной канал — очередь на российском сервере.

Отсутствие полей не является универсальной гарантией, что номер невозможно связать с человеком: до включения оператор должен оценить контекст идентификации и метаданные сервиса. Если уведомление всё же составляет трансграничную передачу персональных данных, требуется исполнение статьи 12, включая отдельное уведомление Роскомнадзора и проверку иностранного получателя. Не включайте передачу содержимого заявки «по галочке».

## Действия владельца до запуска

- Заполнить и утвердить документы и реквизиты, обеспечить действующий канал обращений; не запускать рабочий сбор с плейсхолдерами.
- Подать уведомление о намерении обрабатывать персональные данные в Роскомнадзор, если не применимо конкретное исключение статьи 22; для автоматизированных коммерческих онлайн-заявок обычно требуется уведомление. Проверить реестр и сведения о базе/обработчиках.
- Для юридического лица назначить ответственного, определить доступ и локальные акты; оценить угрозы и требования к защите, реализовать меры статей 18.1/19, порядок ответов, инцидентов и уничтожения. При применимости учесть постановления Правительства № 1119, № 687, приказ ФСТЭК № 21 и приказ Роскомнадзора № 179 об уничтожении.
- Проверить основания повторной публикации имён и текстов отзывов из Яндекса: сама открытость карточки не даёт автоматически права распространять персональные данные на другом сайте (статья 10.1). Согласие формы заявки к авторам отзывов не относится. До публичного запуска подтвердить основание либо обезличить отзывы и оставить ссылку на оригинал.
- Проверить фактическую инфраструктуру на cookies/аналитику. При добавлении трекеров обновить документы и реализовать предварительный выбор там, где обработка требует согласия; рекламное согласие оформлять отдельно, если рассылки действительно появятся.
- Выполнить проверку на настоящем HTTPS-домене: новая заявка, чтение на сервере, отзыв/удаление, просроченные записи, бэкап и отказ уведомления. В этой задаче российский сервер не предоставлен и реальный бот не подключён; облачный запуск не выполнен.
